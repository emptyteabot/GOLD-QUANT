# AURUM回测引擎优化方案

## 📋 当前问题诊断

### 1. 数据样本不足
- **现状**: 仅30天回测周期
- **问题**: 无法覆盖多种市场环境（牛市/熊市/震荡市）
- **影响**: 策略过拟合风险高，泛化能力差

### 2. 交易成本缺失
- **现状**: 无滑点、无手续费
- **问题**: 回测收益虚高，实盘表现差距大
- **影响**: 策略在实盘中盈利能力被高估

### 3. 验证方法单一
- **现状**: 单次回测，无Walk-Forward分析
- **问题**: 无法验证策略稳定性和时间适应性
- **影响**: 策略可能在未来市场失效

### 4. 风险指标不全
- **现状**: 仅有Sharpe比率
- **问题**: 缺少Sortino、Calmar等关键指标
- **影响**: 无法全面评估策略风险特征

### 方案一：扩展回测周期（1年+）

**目标**: 覆盖至少365天历史数据

**实现方式**:
```python
# OKX API限制：单次最多300根K线
# 解决方案：分批获取+拼接

async def get_extended_klines(days=365, timeframe='15m'):
    """
    获取1年历史数据
    - 15分钟K线: 365天 = 35,040根
    - 分批获取: 35,040 / 300 = 117次请求
    """
    all_klines = []
    batch_count = calculate_batches(days, timeframe)

    for i in range(batch_count):
        batch = await okx_client.get_klines(
            inst_id=INST_ID,
            bar=timeframe,
            limit=300,
            after=last_timestamp  # 分页参数
        )
        all_klines.extend(batch)
        await asyncio.sleep(0.2)  # 避免触发限流

    return all_klines
```

**优势**:
- 覆盖多种市场环境
- 提高策略泛化能力
- 减少过拟合风险

### 方案二：添加滑点模型

**目标**: 模拟真实市场的订单簿深度影响

**滑点计算公式**:
```python
def calculate_slippage(order_size, price, orderbook_depth):
    """
    基于订单簿深度的滑点模型

    参数:
    - order_size: 订单大小（张）
    - price: 当前价格
    - orderbook_depth: 订单簿深度数据

    返回:
    - slippage_pct: 滑点百分比
    """
    # 简化模型：滑点与订单大小成正比
    base_slippage = 0.0001  # 基础滑点 0.01%
    size_factor = order_size / 100  # 每100张增加滑点

    # 市场波动率调整
    volatility_factor = get_current_volatility()

    slippage = base_slippage * (1 + size_factor) * (1 + volatility_factor)

    return slippage
```

**滑点等级**:
| 订单大小 | 基础滑点 | 波动率调整 | 总滑点 |
|---------|---------|-----------|--------|
| 小单(<50张) | 0.01% | +0-0.02% | 0.01-0.03% |
| 中单(50-200张) | 0.02% | +0.02-0.05% | 0.04-0.07% |
| 大单(>200张) | 0.05% | +0.05-0.10% | 0.10-0.15% |

### 方案三：添加手续费计算

**OKX手续费标准**:
- **Maker费率**: 0.02% (挂单成交)
- **Taker费率**: 0.05% (吃单成交)

**实现方式**:
```python
class FeeCalculator:
    """手续费计算器"""

    MAKER_FEE = 0.0002  # 0.02%
    TAKER_FEE = 0.0005  # 0.05%

    def calculate_fee(self, order_value, order_type='taker'):
        """
        计算手续费

        参数:
        - order_value: 订单价值（USDT）
        - order_type: 'maker' 或 'taker'

        返回:
        - fee: 手续费金额
        """
        rate = self.MAKER_FEE if order_type == 'maker' else self.TAKER_FEE
        fee = order_value * rate
        return fee

    def apply_to_trade(self, entry_value, exit_value):
        """
        应用到完整交易

        开仓 + 平仓 = 2次手续费
        """
        entry_fee = entry_value * self.TAKER_FEE  # 开仓通常是Taker
        exit_fee = exit_value * self.TAKER_FEE    # 平仓通常是Taker
        total_fee = entry_fee + exit_fee

        return total_fee
```

**影响分析**:
```
假设：
- 初始资金: $1,000
- 杠杆: 10x
- 单笔交易: $10,000 (含杠杆)
- 手续费: 0.05% × 2 = 0.1%

单笔成本: $10,000 × 0.1% = $10
占本金比例: $10 / $1,000 = 1%

结论: 每笔交易需要盈利>1%才能覆盖成本
```

### 方案四：Walk-Forward分析

**概念**: 滚动窗口验证，模拟真实交易中的参数优化过程

**实现流程**:
```
时间轴: |----训练期----|--验证期--|----训练期----|--验证期--|

步骤1: 用前6个月数据训练模型
步骤2: 用后1个月数据验证
步骤3: 滚动窗口，重复步骤1-2
步骤4: 汇总所有验证期结果
```

**代码实现**:
```python
class WalkForwardAnalyzer:
    """Walk-Forward分析器"""

    def __init__(self, train_period=180, test_period=30):
        self.train_period = train_period  # 训练期（天）
        self.test_period = test_period    # 测试期（天）

    async def run_analysis(self, total_data):
        """
        运行Walk-Forward分析

        返回:
        - results: 每个测试期的结果
        - summary: 汇总统计
        """
        results = []

        # 计算窗口数量
        total_days = len(total_data)
        window_count = (total_days - self.train_period) // self.test_period

        for i in range(window_count):
            # 划分训练集和测试集
            train_start = i * self.test_period
            train_end = train_start + self.train_period
            test_end = train_end + self.test_period

            train_data = total_data[train_start:train_end]
            test_data = total_data[train_end:test_end]

            # 训练模型
            model = self.train_model(train_data)

            # 测试模型
            test_result = await self.backtest(model, test_data)
            results.append(test_result)

        # 汇总结果
        summary = self.summarize_results(results)
        return results, summary
```

**评估指标**:
- **稳定性**: 各测试期收益率的标准差
- **一致性**: 盈利期数 / 总期数
- **衰减率**: 收益率随时间的变化趋势

### 方案五：多市场环境测试

**目标**: 验证策略在不同市场状态下的表现

**市场分类**:
```python
class MarketRegimeDetector:
    """市场状态检测器"""

    def detect_regime(self, klines_df):
        """
        检测市场状态

        返回: 'bull' | 'bear' | 'sideways'
        """
        # 计算趋势强度（ADX）
        adx = self.calculate_adx(klines_df)

        # 计算价格趋势（线性回归斜率）
        slope = self.calculate_trend_slope(klines_df)

        # 分类逻辑
        if adx > 25:  # 强趋势
            if slope > 0:
                return 'bull'    # 牛市
            else:
                return 'bear'    # 熊市
        else:  # 弱趋势
            return 'sideways'    # 震荡市

    def split_by_regime(self, klines_df):
        """
        按市场状态分割数据

        返回:
        - bull_periods: 牛市时段
        - bear_periods: 熊市时段
        - sideways_periods: 震荡市时段
        """
        regimes = []
        for i in range(len(klines_df)):
            window = klines_df[max(0, i-50):i+1]
            regime = self.detect_regime(window)
            regimes.append(regime)

        # 分组
        bull_periods = [i for i, r in enumerate(regimes) if r == 'bull']
        bear_periods = [i for i, r in enumerate(regimes) if r == 'bear']
        sideways_periods = [i for i, r in enumerate(regimes) if r == 'sideways']

        return bull_periods, bear_periods, sideways_periods
```

**分环境回测**:
```python
async def test_by_market_regime(engine, klines_df):
    """按市场环境分别回测"""

    detector = MarketRegimeDetector()
    bull, bear, sideways = detector.split_by_regime(klines_df)

    results = {
        'bull': await engine.run_backtest(klines_df.iloc[bull]),
        'bear': await engine.run_backtest(klines_df.iloc[bear]),
        'sideways': await engine.run_backtest(klines_df.iloc[sideways])
    }

    return results
```

### 2. Sortino比率（新增）
```python
def calculate_sortino(returns, risk_free_rate=0):
    """
    Sortino比率：只考虑下行波动

    优势：更关注亏损风险，忽略上行波动
    """
    excess_returns = returns - risk_free_rate
    downside_returns = returns[returns < 0]
    downside_std = np.std(downside_returns)

    sortino = np.mean(excess_returns) / downside_std
    return sortino
```

### 3. Calmar比率（新增）
```python
def calculate_calmar(total_return, max_drawdown, years):
    """
    Calmar比率：年化收益 / 最大回撤

    优势：直观反映收益与风险的平衡
    """
    annual_return = (1 + total_return) ** (1 / years) - 1
    calmar = annual_return / max_drawdown
    return calmar
```

### 4. 信息比率（新增）
```python
def calculate_information_ratio(returns, benchmark_returns):
    """
    信息比率：超额收益 / 跟踪误差

    优势：衡量相对基准的表现
    """
    excess_returns = returns - benchmark_returns
    tracking_error = np.std(excess_returns)

    ir = np.mean(excess_returns) / tracking_error
    return ir
```

## ⚠️ 注意事项

### 1. API限流
- OKX限制：每秒20次请求
- 解决：添加延迟（0.1-0.2秒/次）

### 2. 内存管理
- 1年15分钟K线 = 35,040条数据
- 解决：分批处理，及时释放内存

### 3. 计算时间
- Walk-Forward分析耗时较长
- 解决：使用异步并发，显示进度条

### 4. 过拟合风险
- 参数过多可能导致过拟合
- 解决：使用正则化，交叉验证
