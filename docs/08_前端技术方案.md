### 3.4 实时数据推送

**WebSocket服务**:
```typescript
class WebSocketService {
  private ws: WebSocket;
  private handlers: Map<string, Set<MessageHandler>>;

  connect() {
    this.ws = new WebSocket(WS_URL);
    this.ws.onmessage = (event) => {
      const message = JSON.parse(event.data);
      this.handleMessage(message);
    };
  }

  subscribe(type: string, handler: MessageHandler) {
    // 订阅特定类型的消息
  }
}
```

**自动重连机制**:
- 指数退避算法（1s → 2s → 4s → 8s → 16s → 30s）
- 最大重连次数：5次
- 连接状态提示

## 8. 部署方案

### 8.1 Vercel部署（推荐）

**优势**:
- 自动CI/CD
- 全球CDN加速
- 零配置部署
- 免费SSL证书

**步骤**:
```bash
# 1. 安装Vercel CLI
npm install -g vercel

# 2. 登录
vercel login

# 3. 部署
vercel

# 4. 生产部署
vercel --prod
```

**环境变量配置**:
在Vercel Dashboard中配置：
- `NEXT_PUBLIC_API_URL`
- `NEXT_PUBLIC_WS_URL`

### 8.2 Docker部署

**Dockerfile**:
```dockerfile
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:18-alpine AS runner
WORKDIR /app
COPY --from=builder /app/.next ./.next
COPY --from=builder /app/public ./public
COPY --from=builder /app/package*.json ./
RUN npm ci --production
EXPOSE 3000
CMD ["npm", "start"]
```

**部署命令**:
```bash
# 构建镜像
docker build -t aurum-dashboard .

# 运行容器
docker run -p 3000:3000 \
  -e NEXT_PUBLIC_API_URL=http://api.example.com \
  aurum-dashboard
```

### 8.3 Nginx反向代理

**配置示例**:
```nginx
server {
  listen 80;
  server_name dashboard.aurum.com;

  location / {
    proxy_pass http://localhost:3000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection 'upgrade';
    proxy_set_header Host $host;
    proxy_cache_bypass $http_upgrade;
  }

  # WebSocket支持
  location /ws {
    proxy_pass http://localhost:8000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "Upgrade";
  }
}
```

## 12. 技术债务

### 12.1 已知问题

1. **WebSocket重连逻辑**: 需要优化重连策略，避免频繁重连
2. **图表性能**: 大数据量时图表渲染卡顿，需要优化
3. **类型定义**: 部分API响应类型不完整，需要补充
4. **错误处理**: 部分组件缺少错误边界

### 12.2 技术选型风险

1. **Next.js App Router**: 相对较新，生态不够成熟
2. **Lightweight Charts**: 文档不够详细，定制困难
3. **Zustand**: 缺少DevTools，调试不便

### 12.3 解决方案

- 定期重构代码，消除技术债务
- 关注技术社区动态，及时升级依赖
- 建立技术评审机制，避免引入新的技术债务
